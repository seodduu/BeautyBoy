### 1-1. `frontend/.env.example`의 토스 키 계열 불일치 — ❌ 안 함 (2026-07-28 결정)

> §1-2(실결제 승인)를 하지 않기로 하면서 함께 종결. 검증된 키 쌍 없이 미검증 값을
> 커밋하지 않는다는 원칙에 따라 `.env.example`은 현 상태로 둔다. 아래는 당시 진단 원문.

**증상**: README를 그대로 따라 `.env.example`을 복사한 사람은 **결제가 안 된다.**

`frontend/.env.example`이 `VITE_TOSS_CLIENT_KEY=test_gck_docs_...`(**결제위젯** 계열)인데,
`frontend/src/features/payment/toss.ts:26-28`은 `tossPayments.payment({ customerKey })` +

### 결함

주석은 "차감은 Wave 3의 몫"이라고 적었지만 **실제로 어디에도 구현되지 않았다.**

**조건부 갱신의 영향 행 수로 성공/실패를 가른다:**

```sql
UPDATE goods_option SET stock = stock - :qty WHERE id = :id AND stock >= :qty
```

영향 행이 1이면 확보, 0이면 품절. **Task 4-16a가 리프레시 토큰에 쓴 것과 정확히 같은 패턴이고,

타입이 달라 실 MySQL에서 조용히 깨진다. 이 프로젝트엔 H2가 실 MySQL 문제를 가린 이력이 있다).

### 판단해야 할 지점 (계획서에 못 박을 것)

- **차감 시점**: 주문 생성 시점인가, 결제 승인 시점인가. 주문 생성에서 깎으면 결제를 안 한
  주문이 재고를 잠그고, 승인에서 깎으면 승인은 됐는데 재고가 없는 상황이 생긴다.
- **실패 시 복원**: 결제 실패·취소 시 어떻게 되돌리는가. 복원 누락이 재고 유실을 만든다.
- **부분 실패**: 여러 상품 중 하나만 품절이면 이미 깎은 것들을 어떻게 처리하는가.
- **오늘드림의 `store_stock`과의 관계**: 위 주석이 경고한 "두 벌의 재고 개념"을 어떻게 피하는가.

**`CLAUDE.md`의 모델 배분에서 이 영역(돈·재고 정합성, 오늘드림 재고 차감)은 opus 예외다.**

### 5-1-a. 브레이크포인트 9종 수렴 — ❌ 안 함 (2026-07-29 결정)

§5-1의 햄버거 항목이 "브레이크포인트도 7종이 혼재해 시스템이라기보다 임기응변"이라고 적은
부분이다. 실측은 **9종 35회**(900px 14 / 768px 8 / 640px 5 / 767px 3 / 480·600·820·1024·1440
각 1). 이 중 `767px` 3곳만 오타 수정으로 `768px`에 맞췄고(`a317570`), **나머지 수렴은 하지
않는다.** 근거:

1. **손님에게 보이는 손해가 없다.** 증상 조건이 "창을 850px 근처로 맞춤"(900px과 768px 축이
   갈리는 구간)이거나 "화면 폭이 정확히 768px"이다. 390px 실측에서 12개 화면 전부 **가로
   오버플로 0**이었다 — 모바일 실사용에서 깨지는 지점이 아니다.
2. **비용이 §5-1에서 가장 크다.** 숫자를 옮기면 접히는 시점이 바뀌므로 CSS 21개 파일 35개
   규칙에 대해 화면 전수 스크린샷 대조가 필요하다. 이번 계획의 나머지 전부를 합친 것보다 크다.
3. **부채가 자라지 않는다.** 1차 MVP 완성 상태라 새 화면이 대량 추가될 계획이 없다.
   "지금 안 하면 나중에 더 비싸진다"가 성립하지 않는다.

**인지하고 우선순위를 매긴 부채**와 **방치된 부채**는 다르므로 `DESIGN.md`의 Breakpoints 절
아래에도 같은 결정을 기록했다. 상세는 `docs/plans/2026-07-29-carryover-5-1.md` §6.

**곁들여 확정한 것 — 폼 입력(라디오·체크박스)의 터치 타깃은 애초에 문제가 아니었다.**
`input` 요소만 재면 13×13으로 보이지만 7곳 전부 `<label>`이 감싸고 있어 **실제 탭 영역은 라벨
카드 전체**이고 이미 44px을 넘는다. 측정은 `el.closest('label') || el`로 해야 한다.
다시 "결함"으로 올라오지 않게 여기 적어 둔다.

경계선에 있는 나머지 타깃(`bb-chip` 57×35, `bb-list-toolbar__pill` 93×38, `bb-tag` 41×27)도
이월한다 — 35~38px은 오탭이 잘 나지 않고, 손대면 목록 툴바 레이아웃이 통째로 밀린다.
