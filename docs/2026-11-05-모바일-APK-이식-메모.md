# 모바일(APK) 이식 메모

작성일: 2026-11-05. 상태: **보류**. 지금은 카메라 피부분석 페이지가 우선이고, 이 문서는 나중에
APK 제출이 필요해졌을 때 다시 읽기 위한 기록이다. 계획서가 아니므로 태스크 분할은 하지 않았다.

## 배경

과제 제출 형태는 "모바일 앱 프론트 + 별도 백엔드" 구조의 APK 다. 참고 예시 두 개:

- https://github.com/Mobile-Programming-A/project-FE (React Native + Expo, Firebase 백엔드, eas.json)
- https://github.com/k-uplift/Fridge_app (Flutter + FastAPI 백엔드, APK 는 Google Drive 링크로 배포)

공통점은 특정 프레임워크가 아니라 "앱 프론트와 백엔드가 분리되어 있고 APK 산출물이 있다" 는 것이다.
뷰티보이는 이미 React 프론트와 Spring 백엔드가 분리돼 있으므로 이 형태에 맞출 수 있다.

## 결정: Capacitor 로 감싼다

| 방식 | 바꾸는 범위 | 기간(추정) | 판단 |
|---|---|---|---|
| **Capacitor 래핑** | 프론트 설정 몇 줄 + `android/` 폴더 | 1~2일 | **채택.** 완성된 MVP 전부 그대로 들어간다 |
| Expo(React Native) 재작성 | 프론트 전부 재작성 | 수 주 | 과제가 RN/Flutter 를 명시할 때만 |
| Flutter 재작성 | 프론트 전부 Dart 로 | 수 주 이상 | 기존 코드 재사용 거의 없음 |

피부분석(카메라 + MediaPipe + 픽셀 계산 + IndexedDB)은 전부 표준 웹 API 라 WebView 에서 그대로 돈다.
Capacitor 의 기본 `androidScheme: 'https'` 덕에 WebView 출처가 `https://localhost` 가 되어
getUserMedia 의 보안 컨텍스트 조건이 앱에서는 자동으로 충족된다.

## 바꿔야 하는 곳 (코드 확인 완료, 2026-11-05 기준)

### 프론트 (2곳)

| 파일 | 현재 | 변경 | 안 하면 |
|---|---|---|---|
| `frontend/src/api/client.ts` | `baseURL: '/api/v1'` (vite 프록시 전제) | `import.meta.env.VITE_API_BASE ?? '/api/v1'` 로, `.env.production` 에 배포 주소 주입 | 요청이 앱 자신(`https://localhost`)으로 감 |
| `frontend/src/features/payment/toss.ts` | `successUrl: ${window.location.origin}/order/complete` | 실기기에서 결제창이 WebView 안에서 돌아오는지 확인. 외부 브라우저로 빠지면 딥링크(`beautyboy://order/complete`) 처리 추가 | 결제 후 앱으로 못 돌아옴 |

그대로 둬도 되는 것: `createBrowserRouter`(Capacitor 가 SPA 폴백 처리), 액세스 토큰(zustand 메모리),
피부분석 코드 전부.

### 백엔드 (2곳)

지금 구조는 "프론트와 백엔드가 같은 출처" 라는 전제 위에 있다. 앱에서는 이 전제가 깨진다.

| 위치 | 현재 | 변경 | 안 하면 |
|---|---|---|---|
| CORS 설정 | **없음** (vite 프록시가 같은 출처로 보이게 해 줘서 불필요했음) | `https://localhost` 허용 + `allowCredentials(true)` | 모든 요청 차단 |
| `backend/.../auth/AuthController.java` `refreshCookie()` | httpOnly 리프레시 쿠키 `SameSite=Lax` | `SameSite=None; Secure` (백엔드가 HTTPS 여야 함) | 로그인은 되지만 액세스 토큰 만료 시(또는 앱 재시작 시) 세션 끊김 |

CORS 와 쿠키는 인증 공통부라 **공유 계약** 으로 보고 계획서를 쓸 때 별도 태스크로 잡는다.

### 안드로이드 프로젝트

- `package.json` 에 `@capacitor/core` `@capacitor/android` `@capacitor/cli` 추가 (공유 계약 변경).
- `android/app/src/main/AndroidManifest.xml` 에 `CAMERA` 권한. Capacitor WebView 는 앱 권한이 있으면
  getUserMedia 요청을 통과시킨다.
- 개발 중 `http://` 백엔드를 쓸 때만 `android:usesCleartextTraffic="true"`. HTTPS 배포 후에는 제거.

## 백엔드 통신 방식

앱은 브라우저와 똑같이 HTTP 로 호출한다. 차이는 프록시가 없어 **절대 주소** 가 필요하다는 것뿐이다.

| 방식 | 앱이 호출하는 주소 | 조건 | 용도 |
|---|---|---|---|
| 맥에 띄우고 같은 와이파이 | `http://<맥 LAN IP>:8080` | 같은 네트워크, 맥 방화벽 허용 | 개발 |
| USB + `adb reverse tcp:8080 tcp:8080` | `http://localhost:8080` | USB 연결 유지 | 개발 |
| **서버 배포** | `https://api.<도메인>` | 백엔드 + MySQL 을 올림 | **제출·시연** |

제출은 배포가 필수다. 평가자가 APK 만 받아 설치했을 때 작성자의 맥이 켜져 있어야 동작하면 시연이
안 된다. 저장소의 `docker-compose.yml` 로 Spring + MySQL 을 그대로 올릴 수 있다. 후보: Oracle Cloud
Always Free, Fly.io, Railway. Cloudflare Tunnel 은 임시 시연용으로만.

흐름: 앱 실행 → WebView 가 APK 안의 `dist/` 를 `https://localhost` 로 로드 → 로그인 요청을 배포 주소로
HTTPS 호출 → JWT 수신 → 이후 요청에 Bearer 헤더 → 토스 결제창(외부) → 앱으로 리다이렉트 → 백엔드 승인
요청(2단계 검증 기존 그대로) → 피부분석은 서버 호출 없이 폰 안에서 처리.

## 빌드 명령

```
cd frontend
npm i @capacitor/core @capacitor/android && npm i -D @capacitor/cli
npx cap init "BeautyBoy" com.beautyboy.app --web-dir dist
npx cap add android
npm run build && npx cap sync android
cd android && ./gradlew assembleDebug
# 산출물: android/app/build/outputs/apk/debug/app-debug.apk
```

제출용 README 에는 Fridge_app 처럼 APK 링크와 이 빌드 명령을 적는다.

## 평가 관점 보강

웹을 감싼 앱은 "모바일 프로그래밍" 과제에서 약해 보일 수 있다. 네이티브 기능을 실제로 쓰는 지점이 있어야
설명이 선다. 피부분석 카메라가 그 역할을 하고, 여기에 `@capacitor/push-notifications`(배송 알림) 또는
`@capacitor/haptics` 를 더하면 예시 프로젝트(GPS 추적, OCR + 알림)와 비슷한 무게가 된다.

## 실기기에서 확인해야 하는 것 (미실측)

1. Capacitor WebView 안에서 getUserMedia 와 MediaPipe 가 도는지. 헤드리스 Chrome 가짜 카메라로만 확인했다.
2. 토스 결제창 왕복. WebView 안에서 돌아오는지, 외부 브라우저로 빠지는지.
3. `SameSite=None` 쿠키로 리프레시가 되는지.
