# 세트 비교 페이지 `/sets` 설계 — /main 탭을 걷어내고 전용 화면으로

작성일: 2026-07-28. 상태: 사용자 승인 완료(구현 계획 대기).
선행 설계: `2026-07-28-concept-sets-design.md` (컨셉 파생·조합 로직은 그 문서가 진실).

## 1. 배경 — 무엇을 바꾸고 왜 바꾸는가

선행 구현(`feature/concept-sets`, 8커밋)은 `/main` 히어로 아래에 컨셉 세트 pill 탭 3개를 넣고,
탭 선택이 아래 5단계 조합기를 그 컨셉으로 재조합하게 했다. 실물을 브라우저에서 확인한 결과
두 가지 문제가 드러났다:

1. **한 번에 한 세트만 보인다.** 탭을 오가며 기억으로 비교해야 해서 "세트를 고른다"는 목적이
   약해진다. 사용자는 세 세트를 **나란히 놓고 비교**하기를 원한다.
2. **상단이 답답하다.** `.bb-main__body`에 top 여백이 없어(`Main.css:52-56`) 히어로 검정 밴드가
   끝나는 즉시 흰 영역 첫 픽셀에 `PERSONAL SETS` 아이브로우가 붙는다.

따라서 세트 비교를 **전용 페이지 `/sets`**로 옮기고, `/main`은 원래 모습으로 되돌린 뒤
히어로 밴드 안에 진입 링크 하나만 남긴다.

## 2. 결정 요약 (브레인스토밍 Q&A)

| 질문 | 결정 |
|---|---|
| 세트 하나가 보여줄 것 | **전체 5단계** — 클렌징~선케어 5개 상품을 다 보여준다(요약 카드 아님) |
| 펼칠 위치 | **별도 페이지 `/sets`** — /main 본문과 겹치지 않게 |
| 세트별 액션 | **이 세트 통째로 담기** — 버튼은 밴드 하단이 아니라 **세트 제목과 같은 줄** |
| /main 진입점 | **히어로 검정 밴드 안**, 설명문 아래 흰 화살표 링크 |

## 3. `/main` — 원래대로 복원 + 링크 하나

### 3.1 제거

- `SetTabs` 컴포넌트 렌더와 스켈레톤 분기를 `Main.tsx`에서 제거한다.
- `deriveSetConcepts` 호출, `selectedSet` 상태, `meQuery`/`meSettled` 게이트를 제거한다.
- `useComposer()`를 **인자 없이** 호출한다 → 프로필 고민 전체로 조합하던 선행 동작으로 복귀.
  (`useComposer`의 `concernOverride` 파라미터 자체는 남긴다 — `/sets`가 쓴다.)

### 3.2 히어로 밴드 안 링크

`bb-main__intro-inner`의 lede(`bb-main__lede`) 아래에 링크를 하나 둔다.

- 문구: `컨셉별 세트 보러가기 →`
- 이동: `/sets` (react-router `Link`)
- 스타일: 검정 밴드 위이므로 **흰 글자 텍스트 링크**. 밴드 안이라 DESIGN.md의
  "검정 알약은 화면당 하나(픽 카드 `바로 담기`)" 규칙과 충돌하지 않는다 —
  **채움 버튼을 만들지 않는다.**

### 3.3 상단 여백 해소

`.bb-main__body`에 상단 여백을 준다. 밴드가 끝나고 흰 영역이 시작된 뒤 앵커 네비까지
숨 쉴 공간이 생겨야 한다.

- **검증 가능한 기준**: 히어로 밴드 하단 경계와 앵커 네비 상단 사이 흰 여백이
  **`--space-xl` 이상**일 것. (현재는 0이다.)
- 값은 `DESIGN.md` spacing 토큰에서 고르고 hex/px를 손으로 적지 않는다.

## 4. `/sets` — 신규 페이지

### 4.1 라우트

`router.tsx`에 `/sets`를 추가하고 `RequireAuth`로 감싼다(`/main`과 동일 취급 —
프로필 기반 화면이라 로그인 필수).

### 4.2 레이아웃

```
당신을 위한 세트 3가지
(프로필 없으면) 프로필을 등록하면 맞춤 세트로 바뀌어요 [프로필 등록하기]

┌──────────────────────────────────────────────────┐
│ 세트 A · 브라이트닝              [이 세트 5개 담기]│  ← 헤더 행: 제목 좌, 액션 우
│ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐          │
│ │클렌징│ │토너 │ │세럼 │ │크림 │ │선케어│          │  ← 5단계 가로 한 줄
│ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘          │
├──────────────────────────────────────────────────┤
│ 세트 B · 안티에이징              [이 세트 5개 담기]│
│  … 같은 구조                                      │
├──────────────────────────────────────────────────┤
│ 세트 C · 진정                    [이 세트 5개 담기]│
└──────────────────────────────────────────────────┘
```

- 세트 밴드 3개가 **세로로** 쌓인다. 밴드 사이는 hairline 또는 여백으로 구분(DESIGN.md에 명시).
- 각 카드는 그 단계의 **픽 1개**를 보여준다(대안은 보여주지 않는다 — 비교 화면이므로
  선택지를 늘리면 목적이 흐려진다). 카드에는 단계명(예: `01 클렌징`)을 붙여 어느 단계인지 드러낸다.
- 개별 상품 담기는 카드에서 그대로 가능해야 한다.

### 4.3 조합

`useComposer(slug)`를 세트별로 한 번씩 **총 3회** 호출한다. 훅 호출 횟수가 고정(3)이라
훅 규칙에 안전하다. `SET_COUNT`가 3이라는 전제에 의존하므로, 그 상수와 호출 수가 어긋나면
안 된다는 점을 코드 주석에 남긴다.

- 단계별 후보 풀 쿼리 키는 `['routine-pool', categoryCode]`라 **세 세트가 캐시를 공유**한다
  → 실제 풀 조회는 5회.
- 궁합 게이트(`['compat-verdicts', base, cat]`)는 base가 세트마다 달라 자연히 분리된다.
- 궁합·규칙 조회 실패 시 인기순 기준선으로 진행하는 기존 정책을 그대로 상속한다.

### 4.4 담기

`/main`의 일괄 담기 로직(`Main.tsx`의 `handleAddAll` — 실패는 건너뛰고 집계 토스트로 안내,
전량 롤백하지 않음)을 **공용 함수로 추출**해 `/main`과 `/sets`가 같이 쓴다.

- 추출 위치: `frontend/src/features/routine/` 아래 (정확한 파일명은 구현 계획에서 확정).
- 시그니처는 `queryClient`, 담을 `goodsNo[]`, 토스트 함수를 받아 `{ added, skipped }`를 돌려주는
  형태로 한다 — 화면이 문구를 정하고 함수는 결과만 돌려준다.
- **추출 전후로 `/main`의 기존 담기 동작과 그 테스트가 그대로 통과해야 한다.**

### 4.5 폴백

프로필이 없거나 `['me']` 조회에 실패하면 선행 설계 그대로 **모공·트러블·보습** 3종
(`FALLBACK_CONCEPTS`)으로 밴드를 구성하고, 페이지 상단에 `프로필을 등록하면 맞춤 세트로
바뀌어요` + 프로필 등록 링크를 둔다. (`/sets`도 `RequireAuth` 뒤이므로 링크는 마이페이지
프로필 하나뿐 — 가입 링크 분기를 만들지 않는다.)

## 5. DESIGN.md 변경

`set-tabs` 절을 **`sets-page`** 절로 교체한다. 담을 내용:

- 세트 밴드 구조(헤더 행 + 5칸 가로), 밴드 간 구분과 간격
- 헤더 행: 제목 좌 / 액션 우 정렬, 액션 버튼 변형(고스트 — 픽 카드 담기와 겹치지 않게)
- 폴백 안내 줄
- 로딩 상태(공용 `{Skeleton}` 사용, 확정 후 높이가 흔들리지 않을 것)
- 모바일(768px 미만): 5칸이 한 줄에 안 들어가므로 **가로 스크롤**로 처리
- 한글 적용(자간·행간, `word-break: keep-all`)

`/main` 히어로 링크 사양도 히어로 절에 한 줄 추가한다(밴드 위 흰 텍스트 링크, 채움 금지).

## 6. 에러 처리 · 폴백 요약

| 상황 | 동작 |
|---|---|
| 프로필 없음 / `['me']` 실패 | 폴백 3종 밴드 + 등록 유도 문구 |
| 규칙·궁합 조회 실패 | 기존 조합기 정책 상속(reason 없이·게이트 없이 진행) |
| 어떤 단계의 풀이 비었음 | 그 칸만 비고 나머지 4칸은 정상 — 밴드 전체가 사라지지 않는다 |
| 담기 중 일부 품절 | `N개 담았어요 — M개는 품절로 제외` (기존 문구 체계 유지) |

## 7. 테스트

### `/main` 회귀
- 세트 탭이 **더 이상 렌더되지 않는다**(`queryAllByRole('tab')`이 빈 배열).
- 히어로에 `/sets`로 가는 링크가 있다.
- 선행 구현 이전의 기존 케이스 전부 통과 — 특히 콜드스타트(픽이 인기 1위, reason 없음)가
  **다시 성립**해야 한다(오버라이드가 사라졌으므로).

### `/sets`
| 케이스 | 단언 |
|---|---|
| 프로필 회원 렌더 | 밴드 3개, 제목이 `세트 A · <컨셉>` 형식, 각 밴드에 5칸 |
| 세트별 담기 | 헤더 행 버튼 클릭 시 그 세트의 픽 5개가 담긴다(다른 세트 것이 섞이지 않는다) |
| 일부 품절 | 집계 문구가 `N개 담았어요 — M개는 품절로 제외` 형태로 나온다 |
| 프로필 미입력 회원 | 밴드 라벨이 모공·트러블·보습, 등록 유도 문구가 보인다 |
| 세트 차별화 | 세 밴드의 세럼 단계 픽이 서로 다르다(시드 기준) |

### 공용 담기 함수
- 전량 성공 / 일부 실패 / 전량 실패 3케이스에서 `{ added, skipped }`가 정확하다.
- 실패가 있어도 성공분은 담긴 채로 남는다(롤백하지 않는다).

## 8. 범위 제외 (YAGNI)

- 세트 선택 상태를 `/main`에 반영(선택 저장·URL 동기화)
- 세트 공유·북마크
- 세트 간 가격 합계 비교
- 대안 상품 노출(밴드는 픽만 보여준다)
